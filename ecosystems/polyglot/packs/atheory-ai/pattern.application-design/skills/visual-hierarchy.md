# Make task priority visible

Visual hierarchy communicates the current subject, the relationships between information, and what matters next. Establish it through grouping, alignment, spacing, typography, and restrained emphasis. Hierarchy supports the task; it does not mean making every panel title large or every action colorful.

Group information that people interpret or act on together. Use spacing consistently to distinguish a group from its neighbors, and align repeated items so their differences can be scanned. Choose a small set of text roles for page titles, section labels, values, and supporting explanations. Meaning should remain understandable through structure and words when color is unavailable.

A primary action is primary within a task context. The main document operation and an inspector's local Apply action can coexist when their grouping and targets are clear. Repeating equal emphasis across unrelated actions makes that distinction harder to perceive.

## Example

A node editor gives its subject name and editable settings clear structure. Help text is subordinate but readable. Run status is visible without turning the entire inspector into an alert. The document's Run action and the node's Apply action stay near their respective subjects.

## Verify

The rendered interface makes the current subject, related fields, status, and next action identifiable. Text enlargement and long labels retain meaningful grouping. Web heading levels describe content structure rather than desired font size; [GOV.UK heading guidance](https://design-system.service.gov.uk/styles/headings/) illustrates this distinction.
